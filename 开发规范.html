# 🛠️ MaaPvz 开发规范

📖 读者：二开内容作者（写 pipe / 配作业集）+ 进阶开发者（写 Custom）
ℹ️ 本页原则

只写这个仓库特有的、不写就踩坑的规则；每条规则都带仓库里的真实例子；能一行说清的不写两行。

# 一、Pipeline 命名规范（本篇重点）

1.1 节点名：三段式 模块_动作[_子动作]

节点名一律中文、下划线分段、模块名开头。看到名字就知道它属于哪个功能、干什么：

无尽挑战_选取植物              模块=无尽挑战  动作=选取植物
无尽挑战_识别开始战斗_清空卡牌  子动作=清空卡牌（识别到开始战斗后点掉）
签到_领取奖励                 模块=签到

模块名 = 功能域，与目录对应（见 1.4）。跨任务复用的识别 / 动作进 通用_ 家族：

通用_重开_暂停    通用_点波    通用_无尽_识别结算    通用_神器补给_确定1
🚫 禁忌
  • 不起拼音名 / 英文名；
  • 不新开模块词（要加功能先归到既有模块，实在没有再加新词）；
  • 名字里不用空格；
  • 同一界面只认一个名字（别 开始战斗 / 点开始战斗 混用）。

1.2 特殊节点家族（看到这类名字就知道它的角色）

家族命名角色实例
任务入口 xxx_前置检查 interface.json 的 task.entry 指向它；负责开局定位与状态确认 签到_前置检查、无尽挑战_前置检查_ref（全库 12 个）
闸门 故意不写 recognition 的节点 默认 DirectHit 永远命中，走不走由运行时翻 enabled。目前只在无尽挑战-作业集实装 无尽挑战_跳转_未变 / 无尽挑战_跳转_变化
初始化坐标家族 种植物_初始化_格子{列}_{行}、神器_初始化_xxx、槽Nxxx 节点名与坐标表 agent/assets/resource/coords.json 的键同名，编译器按名字翻坐标。
⚠️ 这套 pipe 节点家族是旧逻辑，强烈不建议使用：pipe 加载耗时很长，迟早被 Custom 代替——目前还留着的都是没重构的代码，打算重构时一并代替。
✅ 而 coords.json 坐标表本身是新逻辑，推荐使用（由 Custom 查表使用）。		 种植物_初始化_格子2_3、神器_初始化_相机复制
占位 / 自回跳 节点把自己的裸名放进自己 next 末尾 识别不到就重试，链条不断。有时会出现点了但没反应的情况，此时 next 链路以自己为末尾，会节省 [JumpBack] 所需的额外算力 "next": ["无尽挑战_神器界面", "无尽挑战_选取神器"]

1.4 文件组织

  • 按功能分目录：Endless_ref/（无尽重构）、pair_duel/（双人对决）、Secret_realm/（时空秘境）、General_action/（通用动作）……
  • 文件名编号前缀表示流程阶段：01_xxx.json → 02_xxx.json → 03_xxx.json；多级用 0300 / 0301 / 03-1-01 这种展开编号。
  • custom_xxx.json = 该功能里 Custom 节点的集中地（习惯约定，非强制）。
  • 一个文件只装一段连续流程（如 04_Endless_Supply.json = 补给屏这一段），文件之间靠节点名接力。
  • MAA 加载时把所有 pipeline JSON 合并成一张全局节点表（没有 import 概念）：A 文件的节点想跳 B 文件的节点，next 里直接写对方裸名即可。
  • 因此节点名全库唯一：同名节点后加载的文件会顶掉先加载的（加载顺序是文件枚举序，不可依赖）——别起重名。

人话：同一个字段不能同名，更建议在写节点名字之前多加前缀；如果你在重构，也可以在有冲突的字段前面加个 ref。

💡 _ref 重构标记约定
  • 文件名带 _ref 的，一般都是重构过的版本；
  • 如果你有重构某个功能的想法，推荐在末尾标记 ref / ref_v0；
  • 如果想在 ref / ref_v0 之上继续重构：新开分支，文件名改成 ref_v1，逐步往上。

1.5 interface.json 侧的命名

  • task.name = 用户可见名（GUI 任务列表显示它）；
  • task.entry = 指到该任务的 xxx_前置检查 节点；
  • task.option = 引用 interface.json option 区定义的选项名；
  • 新增任务的最小闭环：pipeline 里写 xxx_前置检查 链 → interface.json 注册 task。

assets/resource/task 内部的 JSON 通过 interface.json 的 import 字段引用，部分有标注：

"import": [
    // 根目录 task 下的通用功能
    "./resource/task/plants_explore_debris.json",
    "./resource/task/fragment_challenge.json",
    "./resource/task/get_gold_coins.json",
    "./resource/task/Start_game/Start_game.json",
    "./resource/task/Start_game/Start_game_too.json",
    "./resource/task/Secret_realm.json",
    "./resource/task/pair_duel.json",
    "./resource/task/mini_tools.json",
    "./resource/task/test.json",
    "./resource/task/video_card.json",
    // Endless 重构版入口（旧 Endless/* 13 个文件已随重构删除，2026-10-09 清理引用）
    "./resource/task/Endless_ref/Endless_ref.json" // 重构后的无尽入口
],
  • interface 内部一般都只注册入口；
  • 如果发现下面有遗留的字段没有跑去 task 注册，那多半是懒b鼠头忘记了被遗留了——欢迎帮忙注册并提交 PR！

1.6 注释与覆盖标记（JSONC）

  • 管线文件是 JSONC：// 行注释（含行尾）、/* */ 块注释都合法；
  • 被运行时接管的字段旁边有 //会被覆盖 行尾注释，并注明同步哪个快照——看到这个标记就别在 pipe 里单独改它；
  • 注释写「为什么」不写「是什么」，踩坑史带日期：
    // ★ timeout=60s：关卡加载慢于 20s 会误判失败（2026-10-09 日志）

# 二、文件位置规范

ℹ️ 原则一句话

新东西只有一个正确位置——放错地方，运行时找不到或构建时丢了。

2.1 四大块各管什么

位置放什么
assets/resource/pipeline/<功能>/流程节点（JSONC），按功能分目录、编号前缀分阶段
assets/resource/image/<功能目录>/图片模板（识别用截图）；按功能建目录——比如做了「开始登录」，它要用的图集基本就放在新建的 开始登录/ 文件夹里；除非有通用字段需要修改，那是 General/ 管的（存放很多功能通用的截图字段）
assets/resource/task/<功能>.json该功能的 option 定义（case 列表 + pipeline_override）；没有选项的功能不需要这个文件
assets/interface.json任务注册区：GUI 任务清单（name / entry / option）
agent/Custom 动作 Python（maa 依赖只允许出现在这一侧）
game_assist_tools/endless_setup/作业集编辑器（独立 Flask 小工具，前端 static/js 按编号加载）
💡 植物图片资源

位于 assets/resource/image/General/plant/ 内部的文件夹里。建议在无尽正赛截图，这样无尽和普通关卡都可以选取上。

2.2 新增一个功能的落点清单（按顺序落地）

  1. pipeline/<功能>/01_xxx前置检查.json —— 节点流，入口节点叫 xxx_前置检查；
  2. task/<功能>.json —— 有 GUI 选项才建，写 option / case；
  3. interface.json —— task 区注册（name 用户可见、entry 指前置检查、option 引用第 2 步的名字）；
  4. agent/xxx.py —— 需要 Custom 才建，且必须在 agent/main.py 加一行 import（不 import 装饰器不执行，等于没注册）；
  5. 编辑器功能 → static/js/NN-*.js（NN 编号 = 加载顺序，架构见 endless_setup/HANDOFF.md）。

2.3 永不入库的位置

🚫 永不入库
  • assets/debug/、agent/debug/、maa 日志、构建产物 maapvz_pkg_* —— 本地临时物；
  • 任何含绝对路径的文件 —— 打包到用户机器必然失效（所有路径从 __file__ 相对推算）。
