# 二、快速上手：开发环境搭建

ℹ️ NOTE

在开始之前请先自行学习 MaaFramework 的开发文档，了解基于 MaaFramework 进行开发所需的基础知识。在学习开发初期遇到的大部分问题你都可以在文档里找到答案。

2.1 开发环境配置

编辑器推荐：我们强烈推荐使用 VSCode 进行开发，因为社区提供了优秀的 Maa Pipeline Support VSCode 插件来进行调试。

必要软件安装：

  • 安装 VSCode —— 代码编辑器
  • 安装 Git —— 版本控制工具
  • 安装 Python —— 开发语言（≥ 3.13，推荐 3.13.x 最新版）
  • 安装 Node.js —— 辅助开发（版本 ≥ 22）

常用开发工具：

工具简介
Maa Pipeline SupportVSCode 插件，提供调试、截图、获取 ROI、取色等功能（强烈推荐）
MaaPipelineEditor任务流程 pipeline 可视化工具（推荐）
MaaLogAnalyzer日志分析工具，用于分析任务流程的执行情况

2.2 Python 安装详情

访问华为云镜像站下载 Python：

ℹ️ NOTE

镜像地址：https://repo.huaweicloud.com/python/3.13.15/
推荐下载：https://repo.huaweicloud.com/python/3.13.15/python-3.13.15-amd64.exe

运行下载的 Python 安装程序，强烈建议勾选 "Add Python to PATH" 选项，然后按照默认设置完成安装。

2.3 克隆项目代码

使用 Git 克隆项目代码到本地：

git clone https://github.com/Maa-Assistant-PVZ-The-best/MAAPVZ.git
cd MAAPVZ
💡 TIP

确保你已经安装了 Git 工具，否则无法执行上述命令。

2.4 下载 OCR（文字识别）资源文件

下载 ppocr_v6.zip 模型压缩包，解压到 assets/resource/base/model/ocr/ 目录下，确保路径如下：

assets/resource/base/model/ocr/
├── det.onnx
├── keys.txt
└── rec.onnx

2.5 安装 Python 依赖

项目使用朴素的 pip 管理依赖（依赖列表见 requirements.txt：maafw、flask、numpy 等），先创建虚拟环境再安装：

# 创建虚拟环境
python -m venv venv
# 激活虚拟环境（Windows PowerShell）
.\venv\Scripts\Activate.ps1
# 安装依赖
pip install -r requirements.txt
⚠️ WARNING

由于项目统一配置了 VSCode 的 Maa 插件调试功能，所以必须要创建虚拟环境。

2.6 验证安装

安装完成后，可以运行项目来验证是否安装成功：

python -m agent.main <identifier>   # <identifier> 替换为 uuid，如 "3be2c931-9c0d-4d69-9ebd-eed2263e06fd"

identifier 属性与值可以放在 assets/interface.json 里的 "agent" 属性中。

✓ 如果能够正常启动，说明开发环境已经搭建完成！

2.7 开始开发

阅读 M9A 开发须知，了解如何在本地以开发模式运行本项目（本项目与 M9A 的项目结构类似，可以作为学习参考）。

如果不会写代码，但对某些功能的实现有明确的思路：

  • 参考 任务流水线（Pipeline）协议 学习如何将思路转化为具体实现；
  • 了解如何在 assets/resource/pipeline 中编写流水线文件；
  • 学习 Project Interface 协议，了解如何让软件能够调用你写的流水线文件。

如果你有一定的 Python 基础，想要尝试为项目编写代码：

  • 阅读 MaaFramework 集成接口 并结合本项目源码，了解如何为项目开发高级功能；
  • 重要提示：纸上学来终觉浅，绝知此事要躬行。不结合代码实践读文档，等于白读。

为项目贡献你所编写的内容，请参考 《牛牛也能看懂的 GitHub Pull Request 使用指南》。

2.9 常见问题与解决方案

运行项目问题：

  • 错误：提示 "Failed to load det or rec"、"ocrer is null" —— 解决方案：确保 MaaFramework 依赖已正确安装，且 OCR 模型文件完整。
  • 错误：提示找不到模块 —— 解决方案：检查是否已正确激活虚拟环境（如果使用了虚拟环境），或重新安装依赖。

# 三、Custom 使用：选择植物 与 组合动作

ℹ️ 分工边界

选卡归 SelectPlants，局内操作归 BatchSwipe。这两个 Custom 是通用件，不依赖任何上层功能——无尽作业集就是用它们实现的（把「选什么卡 + 种在哪个格」翻译成两件的接力）。写新功能照这个模式来，别自造第三套。

# 组合动作 BatchSwipe —— 位置固定、顺序明确的批量手势

接线 = 一个 Custom 节点，参数就是一串 DSL（真实例，地宫 2 boss 关种植）：

"地宫2_boss_种婆罗": {
    "action": "Custom",
    "custom_action": "BatchSwipe",
    "custom_action_param": "@0.1;swipe:种植物_初始化_第五个槽位,种植物_初始化_格子1_1,50"
}

含义：@0.1 是每步动作之间的间隔设定（@N 前缀 = 每步隔 N 秒，不写时默认 0.1s，不是"开头等一次"）→ 然后 swipe: 从「第五个槽位」拖到「格子1_1」（拖 50ms）。种植 = 从卡槽拖到棋盘格；坐标全部写 coords.json（agent/assets/resource/coords.json）的键名，不写像素数字。

DSL 用 ; 把动作串成一串，按用途分组教学：

① 基础动作与间隔

写法作用与例子
click:坐标键点一下（click:确认按钮）
swipe:起点,终点,时长ms拖动（种植就是 swipe:槽位,格子,50）
sleep:秒等待（sleep:0.5）
串首 @N;设定本串每步间隔 N 秒（默认 0.1）

② 重复与节奏

写法作用与例子
动作*n连击 n 次、次间无间隔（click:确认*3）——要结算间隔就写 n 个普通动作，别用 *n
「动作;动作」无间隔包裹块：块内背靠背执行，块外恢复间隔
{!动作;…}异步组：提交后不等待连压队列。实测：异步 ≠ 并发，设备上仍严格串行；需要结算间隔时给组内加 @0.05~@0.1

③ 随机

写法作用与例子
{动作;动作}随机块：块内动作打乱顺序执行
@权重随机元素末尾加权重（{swipe:a,b@2;swipe:c,d@5}，越大越可能排前）
{块A}@3;{块B}@1块间池随机

④ 多指

写法作用与例子
multi:(起1,终1,时长;起2,终2,时长)N 指真正同时滑动（实测 5 指 1ms 内同按）
attach:(动作;…) + attach_every:N附属块：主块每 N 个动作时，另一指同时做一件事
attach_mode:merge / insertmerge = 合成一个 MultiSwipe 真同时；insert = 紧跟串行（最保险）
 
// 种植全程顺带领阳光（真实用法）：
…;attach:(swipe:1阳光起始点,1阳光终点;swipe:2阳光起始点,2阳光终点);attach_every:4;every:5;resume
⚠️ 多指的硬前提

输入法必须是 Minitouch（maa_pi_config.json 里 "input":"3"）——默认的 AdbShell 会让多指静默失效（已实测）。若种植失败，先把 attach_mode 改成 insert 排查。

⑤ 识别到内容后立即停止当前动作链，直接进入 next 链——防止组合动作一直执行下去

写法作用与例子
watch:文本A|文本BOCR 触发：屏上（或 roi 内）出现任一文本即停（watch:已领取|集齐）
watch:@@roi:盒@@compare:<=900数值触发：OCR 区域里的数字按表达式比较（不认文字）
ref:节点A|节点B引用触发：复用已有 pipe 节点的识别，任一命中即停；@inv 反转命中语义
gateref:节点 / guard:节点@@roi:盒守卫：执行的动作进入到这个位置/区域时才识别一次，命中即停并走 next。典型用途：无尽挑战里防误触结算——在点击「可能含结算按钮的位置」之前先识别一次，结算界面出现就立刻停手
every:N / every:block每 N 个动作识别一次 / 每个顺序块结束识别一次（默认每步都识别）
roi:盒1|盒2全局识别范围（盒可写 x,y,w,h 或坐标表键名）

⑥ 固定动作与断点续做

写法作用与例子
fixed:N:动作每 N 个普通动作后额外做一次（fixed:5:swipe:收取按钮,收取框,50）
fixed:block:动作每个「顺序块」结束后做一次（{} 是一块分界）
resume / reset断点续做 / 清断点：命中停批后下次回到本节点，从断掉的那个动作重做。只在当前任务运行内有效（内存，不落盘；重开任务从头来）

# 选择植物 SelectPlants —— 目标要滚动着找的植物选择

在选卡界面按你给的列表选植物：找卡 → 滑屏 → 点选 → 核验（OCR 顶部名字条）→ 拿错了丢回槽位重找，全程容错。教两种模式：

① 局内选卡（按阵容选卡）

"xx_选取植物": {
    "action": "Custom",
    "custom_action": "SelectPlants",
    "custom_action_param": {"植物列表": ["豌豆射手", "向日葵", "..."]}
}
  • 植物列表 必填，按槽位顺序写（第 1 株进槽 1，依次类推）；
  • 不足 8 株会自动「占位填充」把空槽填满（游戏不允许卡槽中间留空）；
  • 找卡过程中会顺带给后面 3 株未选的植物「踩点」，轮到它们时知道先回顶再下翻；
  • 匹配阈值默认 0.90，别调松（0.70 会认错植物）；
  • 无尽挑战里的 无尽挑战_选取植物 节点是另一种用法：参数写 "{}" 占位，阵容由作业集运行时灌注。

标准接线与工作原理

一个可以直接抄的使用案例（静态写法，自己任务里用）：

"我的任务_选取植物": {
    "action": "Custom",
    "custom_action": "SelectPlants",
    "custom_action_param": {"植物列表": ["豌豆射手", "向日葵", "坚果"]},
    "next": ["我的任务_开始战斗"]
}

只写 植物列表 就能跑——滑动、回顶、核对区域、槽位、占位坐标全部有内置默认值（按无尽选卡界面实测：搜索区 [138,389,595,302]、滑动 215,587→215,200 600ms、回顶 381,401→381,611 100ms、核对 roi [258,100,312,46]、匹配阈值 0.90）。界面布局不同时才覆盖对应键：搜索roi / 滑动 / 回顶 / 核对roi / 槽位roi / 槽位坐标 / 占位坐标。

无尽挑战那个节点就是这套默认值的动态版：pipe 写 "{}" 占位，运行时按当前作业集/关卡/普通或 boss 关灌入 {"植物列表": [...]}（其余参数全走内置默认）——静态写死和占位灌注是同一件事的两种写法。这一个节点内部其实做了一整套容错编排：

  1. 顺路踩点：找当前植物的途中，顺带识别它后面 3 株还没选的植物，记录它们出现在第几屏；轮到找下一株时先查记录——记录在上方就直接回弹（滑回最顶上）再往下找，不硬滑到底。
  2. 触底回弹：一路滑到列表尽头时，连续两次识别发现卡槽界面没有变化，也会直接回弹。
  3. 回弹幅度：上滑次数 = 本轮寻找时向下滑动的次数 + 3，确保回到最顶。
  4. 顶部 OCR 核验：每点选一株，都在顶部窗口核对名字。核对失败（要找雷龙草却点成了闪电豌豆，OCR 读出来也是闪电豌豆）→ 立刻取消这张卡，且这张卡进黑名单：后续再识别到也不再点，重新寻找目标植物。
  5. 不足 8 株的保底：你设置的寻找植物不足 8 个时也会回弹，回弹后连续选取剩余植物把卡槽填满——防止因为植物不够导致没办法开始战斗。

② 编队选择（切指定编队）

"xx_切换编队": {
    "action": "Custom",
    "custom_action": "SelectPlants",
    "custom_action_param": {"编队选择": true, "目标编队": 2}
}
  • 目标编队 填 1-6；与「植物列表」互斥，给了编队就走编队模式；
  • 靠编队序号数字的白色状态核对：1 号天生白；选中态变白——目标 ≠1 看到目标变白即成功，目标 =1 看到只剩 1 号白即成功；
  • 滑过头了会靠数字 OCR 判断回弹；滑动按住、核对等待 这类微调参数一般用默认值就够。

中英文对照表：能干什么、什么时候不让写

agent/select_plant/植物中英文对照表.md 是植物名的唯一权威。SelectPlants 靠它把中文名翻成「英文名 + 品质」，再按 plant_ref_card/<品质>_card/<英文名>.png 找卡面模板；皮肤/超装等卡面变体放同名子夹（<品质>_card/<英文名>/），命中其一即算。

⚠️ 没有卡面模板的植物不让写

对照表只是「名册」，登记 ≠ 有图：目前对照表 317 种植物，局内卡面模板只有 248 种，69 种暂缺（向日葵也在缺图名单里）。把没图的植物写进 植物列表，运行时会因「没有模板」直接失败。写之前先确认 assets/resource/image/General/plant/plant_ref_card/<品质>_card/ 下有对应英文名的 png（或同名皮肤子夹）。

OCR 读错的写法登记进代码里的 PLANT_NAME_ALIASES 别名白名单（有时会出现识别错误的情况，一些植物的字体识别成繁体）。核对失败的日志会打出期间 OCR 读到过的所有文本，照那份清单加别名。
